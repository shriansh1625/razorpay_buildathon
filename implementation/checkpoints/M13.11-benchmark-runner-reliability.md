## Root cause of memory growth

Profiling the pre-M13.11 runner (`revive/benchmark/official/runner.py`):

| Retention | Effect at official scale |
|-----------|--------------------------|
| `world_cache: dict[(seed, profile), SharedWorldBundle]` | Up to **120 full worlds** (20 seeds × 6 profiles) held until run end |
| Per-cell simulation state returned from `run_policy_on_world` | Large `ReviveRunState` / `BaselineRunState` kept alive until GC if referenced |
| In-memory `BenchmarkAggregate.per_run` | 600 metric objects (small; not primary driver) |

At official scale (500 opportunities, 21 days, 100 customers), each generated world is large. Caching all seed/profile worlds was the dominant unbounded retention pattern.

**Not the fix:** calling `gc.collect()` alone. **The fix:** cell lifecycle ownership — one shared world per seed/profile group, five sequential policy runs, explicit release, aggregate built from compact persisted cell JSON.

## Architecture change

New package: `revive/benchmark/official/cells/`

| Module | Role |
|--------|------|
| `plan.py` | Canonical 600-cell planner (seed → profile → policy) |
| `store.py` | Atomic cell JSON + checkpoint manifest + validation/resume |
| `runner.py` | Cell-by-cell execution, progress, world group lifecycle |
| `telemetry.py` | Optional RSS/duration telemetry (outcome-neutral) |

`execute_benchmark()` now delegates to `run_cell_benchmark()` for all non-blocked runs.

### Cell execution lifecycle

```text
For each (seed, profile):
  generate ONE shared world (skip if all 5 policies already valid on disk)
  B0 → persist → release policy state
  B1 → persist → release
  B2 → persist → release
  B3 → persist → release
  REVIVE → persist → release
  release shared world
Aggregate from persisted cell summaries → finalize_m10()
```

### Persistence layout

```text
artefacts/benchmark/official/cells/
  checkpoint-manifest.json
  seed-001/BALANCED/B0.json
  ...
```

Each cell file includes: schema version, config hash, benchmark version, policy pack version/hash, metric version, metrics payload, checksum.

Checkpoint manifest: `cells_completed`, `cells_total`, `last_completed_cell`, config hash, benchmark version.

Writes use temp file → atomic rename.

## Checkpoint design

- **Cell result:** validated by schema version, config hash, benchmark version, policy pack version/hash, metric version, metrics checksum
- **Checkpoint manifest:** atomically updated after each successful cell
- **Config mismatch:** `BenchmarkConfigMismatchError` — no resume across frozen config hashes
- **Corrupt cell:** checksum/identity failure → cell recomputed

---

## Resumability

- Valid existing cell → skip (no re-simulation)
- `stop_after_cell` / interrupted run → resume skips completed cells
- Verified: stop after cell 17 → resume completes remaining 18 without duplication
