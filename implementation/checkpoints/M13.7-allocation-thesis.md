## Findings

### Root cause of M13.6 collapse (not M8 defect)

At **500 / 100 / 30-day** official proposal:

- **0** portfolio conflicts detected
- **0** B3/REVIVE differing allocations (18 cells)
- **0** fallback usage (all Lagrangian)
- Identical total ENRV — **case A**: identical candidate selections
- Only **retry_slots** and **human_review_slots** bind; message, voice, incentive, contact do not
- B3 and REVIVE both select **100% retry** category actions (dominant: scheduled payment retry)
- Shadow prices on retry_slots are non-zero but do not change the selected set

At **21-day window** (documented calibration scale) with same 500/100:

- **11,766** portfolio conflicts
- **43** differing B3/REVIVE allocations
- Multiple resources bind (retry, message, human, contact)

**Simulation window length** is the primary discriminator between collapse and differentiation — not opportunity count alone.

### M8 implementation

**ALIGNED** with `docs/10-recovery-allocation.md`. No concrete specification mismatch requiring rewrite.

### B3 implementation

**ALIGNED** with `docs/20-benchmark.md` GREEDY_ENRV definition.

### Fallback

0% at official scale. Collapse is not caused by fallback path.

## Action concentration

Official 30d: candidates span multiple categories, but **selected** actions are 100% retry for both B3 and REVIVE. Homogeneous winners + single binding resource → greedy ENRV optimal.

---

## B3/REVIVE behavior

- Same actions, same ENRV totals
- REVIVE defers more opportunities (portfolio deferral without swap)
- Differentiation requires multi-resource binding or ENRV/density inversions — absent at 30d mid-cycle

## Configuration sensitivity

**LOW-DIFFERENTIATION:** all 500-opportunity / 30-day rows (7 matrix rows)  
**HIGH-DIFFERENTIATION:** all 21-day window scale-sensitivity rows (100–750 opps)

Customer count (50/100/200) at 30d does not restore differentiation.

## Thesis classification

# THESIS CONFIGURATION-DEPENDENT

The portfolio-allocation thesis is valid in principle and M8 implements it correctly, but the **proposed official 30-day configuration does not exercise** multi-resource portfolio conflicts. A legitimate 21-day window configuration does.
