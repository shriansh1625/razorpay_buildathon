## Objective

Optimize M8 Lagrangian allocator implementation without changing allocation semantics, frozen benchmark configuration, or M4–M12 behavior.

---

## Root cause

Confirmed bottleneck in `lagrangian_allocate()`:

- 40 subgradient iterations × up to 500 opportunities × ~6 candidates
- Repeated `_reduced_value_paise` + `usage_dict()` dict copies
- Per-iteration filtered dict reconstruction for usage / contact violation
- **2016 allocation cycles per REVIVE cell** amplifies cost to multi-minute cells

---

## Implementation changes

| Area | Change |
|------|--------|
| `lagrangian.py` | Eligible-candidate prefilter; tuple-based usage iteration; streamlined usage/violation accumulation |
| `resources.py` | `usage_dict` id-cache + `clear_usage_cache()` per allocate call |
| `lagrangian_reference.py` | Frozen pre-optimization reference for regression |
| `tests/allocation/golden/` | Golden allocation fixtures |
| `tests/allocation/test_m13_12_performance.py` | Semantic + performance regression |

**Not changed:** k_max, iteration_budget, duality_tolerance, step rule, objective, constraints, tie-breaking, fallback.
