# M13.21 Decision

## PERFORMANCE RESCUED

**Label:** DEVELOPMENT_FORENSIC_ONLY — NOT OFFICIAL BENCHMARK EVIDENCE

### Root cause

The apparent “regression” vs M13.14 (~480 s REVIVE) is **not primarily a parallelization or M8 regression**. It is the combination of:

1. **M13.14 measured zero-execution cells** — profile artifacts show M11/M12 at 0 s and golden `intervention_count=0`. M13.18 correctly enabled authorization → execution → measurement.
2. **Dominant cost unchanged** — M6+M7 still ~59% of REVIVE wall time (same class as M13.14).
3. **Implementation inefficiency (fixed)** — `resolve_world_opportunity_id_by_natural_key` performed O(N) world scans per selected assignment (~10¹⁵ dict walks/cell). Replaced with cycle-local `index_world_opportunities_by_natural_key`.
4. **ETA math** — measured Run 4 per-policy times (B1 ~400 s, REVIVE ~690 s seed=1 BALANCED) × 600 cells ÷ 2 workers ⇒ **49–57 h is consistent**, not mysterious.
