# M13.23 Decision

## LAGRANGIAN_EQUIVALENCE_RESTORED

Optimized and reference Lagrangian paths are equivalent on the cloud-failing fixture, golden fixtures, official-scale representative cells, and the full 318-test suite.

### Root cause

`usage_dict` was keyed by `id(pc)`. After GC, CPython id reuse attached a stale usage map to a new candidate. Reference used that cache for contact violation; optimized read `pc.usage` directly. One dropped contact changed `contact_v` 2 → 1 and produced **exactly 2×** `λ_contact` (`1042.38` vs `521.19`).

Optimized was not double-counting. Reference was under-counting under a stale cache. Correct `contact_v` is **2**.

### Fix

- Cache `usage_dict` by immutable `pc.usage`, not `id(pc)`
- `clear_usage_cache()` at the start of both `lagrangian_allocate` implementations
- Optimized reduced value / usage / contact violation read `usage_dict` (same last-wins semantics as reference)

### Unchanged

PolicyPack, epsilon, B3, objective, constraints, tie-break, k_max, iteration budget, step rule, official benchmark configuration, golden fingerprints.

Official benchmark was **not** executed.

- `tests/allocation/test_m13_12_performance.py`: 13 passed
- full suite: **318 passed**
