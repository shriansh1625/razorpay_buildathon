# M13.12 Decision

## PERFORMANCE READY

Lagrangian allocator implementation optimizations preserve semantic equivalence (260 tests, golden fixtures, reference comparison, 7 official-scale representative cells) while materially improving runtime.

### Measured improvement

- `lagrangian_allocate`: **~1.63×** mean speedup on representative frozen cells
- 50 REVIVE cycles (seed=2, BALANCED): **30.17 s → 9.63 s** (~**3.1×**)

### Semantic equivalence

- Identical `allocation_hash` on all measured representative cells
- Full `AllocationResult.to_dict()` match vs reference implementation
- Determinism preserved

### Not changed

- Benchmark configuration
- M8 business semantics, constraints, objective, tie-breaking, fallback rules
- Convergence tolerance, iteration cap, step rule

### Blockers removed for review

Primary confirmed bottleneck (`lagrangian_allocate` inner loop) addressed with semantics-preserving precomputation and reduced copying.

### Not addressed (future work)

- M6/M7 candidate generation and valuation (~60% of REVIVE cycle time)
- Cross-cycle lambda warm start (equivalence not proven)
- Mathematical decomposition fast paths (not proven)

Official benchmark remains **explicit user invocation only**.
