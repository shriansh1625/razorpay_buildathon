# M13.22 Decision

## M6_M7_PERFORMANCE_NOT_READY

Identity-preserving M6/M7 work is in place and **semantically exact**, but the official-scale REVIVE cell did **not** meet the ≥1.5× speedup target.

| | |
|--|--|
| Old total cell time (M13.21 loop) | **514 s** |
| New total cell time (M13.22 loop) | **685 s** (this session; no demonstrated speedup) |
| Speedup | **not achieved** |
| M6 old/new | 151 s / 170 s |
| M7 old/new | 157 s / 223 s |
| Peak RSS | ~627 MB |
| Semantic equality | **YES** (15-cycle M6/M7 hashes; `Decimal` rounding preserved) |

### What was tried

- Cell-scoped CandidateConfig / ValuationConfig  
- Module feasibility class table  
- SHA-256 Crockford encoding via digest bytes (bit-identical IDs)  
- Shrinkage n=0 equal-prior mix (bit-identical to three-prior formula)  
- Single `observable_natural_prior` per natural estimate  
- **Rejected:** `round()` instead of `Decimal` bankers rounding (M7 hash changed)

### Remaining bottleneck

M7 integer money via `Decimal(str)` on ~5.5M valuations, plus M6 object/ID volume. Further speedup requires a **proven-identical** money path or reducing object churn without dropping candidates.

### Hard stop

No `revive benchmark --mode official`. Frozen experiment unchanged. Do not start Run 5 from M13.22.
