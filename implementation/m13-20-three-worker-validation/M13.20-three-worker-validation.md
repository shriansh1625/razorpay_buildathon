# M13.20 — Three-Worker Official Runner Validation

**Label:** DEVELOPMENT_VALIDATION_ONLY — NOT OFFICIAL BENCHMARK EVIDENCE

## Scope

Validate `workers=3` parallel execution without changing frozen benchmark configuration.

## CLI

```powershell
revive benchmark --mode development --workers 3 --output artefacts/benchmark/dev-workers-3
```

Progress format (parent process, after group persistence):

```
parallel workers=3 groups=120 cells_planned=600
[GROUP 001/120] seed=1 profile=BALANCED
seed=1 profile=BALANCED: 5/5 policies complete | group_duration=... | rss=...
[001/600] seed=1 profile=BALANCED policy=B0 | ...
progress: groups=1/120 cells=5/600
```

## Validation script

```powershell
python scripts/m13_20_validate.py --output implementation/m13-20-three-worker-validation
```

Optional full 30-cell matrix (seed=1, all 6 profiles):

```powershell
python scripts/m13_20_validate.py --full-matrix
```

Compares workers 1/2/3 on frozen official scale (preflight config, development mode label):

- `metrics_checksum` per cell
- aggregate fingerprint
- REVIVE outcome metrics (allocation effects captured in metrics)
- peak RSS (parent + worker estimate)
- workers=3 resume after `stop_after_cell`

## Memory gate

Estimated parallel peak = `parent_peak + worker_peak × workers`.  
Reject `workers=3` if estimate exceeds **6 GB** (M13.13 feasibility ceiling for ~8 GB machine).
